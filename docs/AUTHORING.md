# 用 Markdown 写课

想改第一课，打开 `content/v1/course/u01/01.md`。每课一个文本文件，包含学习者看到的讲解、引用的原文、知识点和练习。单元检查放在同目录的 `check.md`。日常改题只需文本编辑器或网站里的课稿预览。

## 改一道题

下面从第一课选取一个简化写法。方括号中的 `x` 勾出正确答案。每个干扰项下面用两个空格缩进写下错因。答对时学习者会看到整题解析。

```md
## 单选：这里的“走”最接近哪一种动作？ {#q.fire}
考点：skill.run
语境：p.fire

- [ ] 缓步前行
  理由：“争”与“避”写出逃避火势的急迫，缓行不合语境。
- [x] 奔跑

提示：从“以避之”找众人行动的目的。
解析：众人争相奔跑以躲开火势，“走”在这里指跑。
```

`skill.run` 和 `p.fire` 是同课程中已经登记的知识点和原文。题目、课文、单元等标题末尾的 `{#…}` 是稳定 ID，修改标题或题干时保留它。新 ID 用字母、数字、点、短线和下划线。选项 ID 可以省略，系统会生成 `题目ID.o1`、`题目ID.o2` 等编号；已有学习记录的选项需要调整位置时，保留原来的显式 ID。不要把旧 ID 分配给考查另一义项的新题。

**选段** 把标题中的“单选”改为“选段”，选项文字逐字复制自原文。重复片段在选项下写 `  第几处：2` 等从 1 开始的次数。编译时自动换算 UTF-16 字符位置。**排序** 用“排序”作标题类型，每项写成 `- [2] 打开匣子` 等，括号里填正确次序，文件中的排列是初始展示顺序。解析说明全部事件的依据和先后依赖。

## 给一节课写讲解

课文头部的“简介”出现在路径与课前页。`## 正文` 之后直接用 Markdown 写教学内容，支持小标题、段落、列表、加粗、引用、对照表、代码块和 HTTPS 链接。可先给读者一个能直接观察的现象，再比较两种理解，最后用原文证据排除其中一种。正文到下一个内容章节（如“知识点”“原文”“单选”）结束。

每个“知识点”标题定义一个具体用法。“义项”“领域”“要诀”“讲解”分别用于教学和知识库。“例句”指向该义项的示范原文。每个新知识点自动产生一张知识卡，默认复用本课中该义项的所有题，至少有两段不同文字的原文。如需指定跨课语境，在知识点下写 `复习题：题目ID1 题目ID2`。普通课讲授的每个主要义项都应有练习。

“原文”标题写“教学例句”或“古籍引文”。前者默认项目自撰，译文默认自撰；可用“原文权利”“译注权利”分别覆盖说明。用引用符号 `>` 写原文，在“译文”字段写自撰译意。同一原文只定义一次，多题可以引用同一 ID。古籍引文必须填写“出处”“作者”“版本”“原文权利”“译注权利”，可以加“底本链接”指向核对过的 HTTPS 链接。选段、译文和出处须逐一核对。

字段值可以直接使用中文标点、冒号与方括号；换行继续写同一字段时，用两个空格缩进，选项理由的续行用四个空格。正文使用 Markdown 的反斜杠转义。要在正文演示完整课稿标记，用代码围栏包住，里面的标题不会被识别成题目。

## 排课与通过条件

| 文件 | 编辑内容 |
| --- | --- |
| course.md | 课程名、简介、等级、目标以及“单元”列表 |
| unit.md | 单元名、等级、“课序”列表和“检查”ID |
| 每节课的 .md | 课前正文、知识点、例句与练习；练习按文件顺序出现 |
| check.md | 检查名称与练习；考点应来自本单元，至少涉及每课的一个义项 |

文件名仅用于整理，所有引用按 ID 匹配。“课序”按教学顺序列 ID，中间留一个空格。增加一课时复制邻近课文，给新实体分配 ID，并把课文 ID 加入单元的“课序”。可选择在课文或检查标题后写“通过题数”。默认正课按题数的四分之三向上取整，检查按三分之二向上取整；正课还需覆盖所有主要知识点。

当前文言教材在课程文件声明 `完整性：L1 4 3 8 6 120`，依次代表等级、单元数、每单元课数、每课题数、每次检查题数、总题数。独立的新课程可以自行设置或省略。可运行的微型范例是一门带两个练习、一项检查的气象课，完整源文件在 [example-course](example-course/)。

## 预览、校验与审核

1. 打开[作者预览](https://bzy-debug.github.io/wenyan-app/#/author)，选择已有课文或检查。粘贴或打开同 ID 的 .md，更新预览后可以直接跳转到每题、选择答案并检查反馈。编辑后下载课稿，将它保存回仓库的对应文件。新增课文需先在单元目录登记。
2. 开发时运行 `npm run dev`，保存 Markdown 后开发服务器会重新编译。`npm run validate:content` 在本地检查语法、ID、答案、选段、知识卡、多语境、关卡覆盖与引用关系。报错如 `u01/01.md:48` 中的数字是行号。完整验证依次运行 `npm run check`、`npm run build` 和 `npm run test:e2e`。
3. 原文、知识点、题目、课文和检查默认“草稿”。人工复核后分别写“状态：已审核”和“审核人：…”；发布时用“已发布”。已发布实体所引用的原文、义项或题目也须完成发布。内容修改后按 [内容规范](CONTENT_GUIDE.md) 重新审核。

构建工具把 Markdown 编译为带类型的数据模块；学习端直接使用编译结果。浏览器作者预览、Node 内容校验和生产构建共用同一套编译逻辑。无需手工生成或同步另一份题库。
