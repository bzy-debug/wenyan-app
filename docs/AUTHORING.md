# 用 Markdown 写课

想改第一课，打开 `content/v1/course/u01/01.md`。每课一个文本文件，包含学习者看到的讲解、引用的原文、知识点和练习。单元检查放在同目录的 `check.md`。日常改题只需文本编辑器或网站里的课稿预览。

## 改一道题

下面是第一课中驿卒报信的一题。方括号中的 `x` 勾出正确答案。每个干扰项下面用两个空格缩进写下错因。答错时学习者会看到对应选项的理由。详解供答后主动展开。

```md
## 单选：“走告里人”写谁去报信，又是怎么去的？ {#q.2}
考点：skill.run
语境：p.l1.1.r1

- [x] 跑去给附近的人报信 {#q.2.o1}
  理由：水已经涨急，驿卒奔跑报信，居民这才来得及撤开。
- [ ] 步行去通知附近的居民 {#q.2.o2}
  理由：“水声甚急”，桥眼看就要塌。这里的“走”是跑，不能照今天“走过去”的意思读。
- [ ] 居民跑来给守桥的驿卒报信 {#q.2.o3}
  理由：“闻水声”的是驿卒，接下来“走告”的还是他；“里人”是听他报信的人。

提示：把“走告”和末尾“无一人伤”连起来。
解析：水已经涨急，驿卒奔跑报信，居民这才来得及撤开。
```

`skill.run` 和 `p.l1.1.r1` 是同课程中已经登记的知识点和原文。题目、课文、单元等标题末尾的 `{#…}` 是稳定 ID，修改标题或题干时保留它。新 ID 用字母、数字、点、短线和下划线。选项 ID 可以省略，系统会生成 `题目ID.o1`、`题目ID.o2` 等编号；已有学习记录的选项需要调整位置时，保留原来的显式 ID。不要把旧 ID 分配给考查另一义项的新题。

**找原文证据** 用“找原文证据”作标题类型，题干问人物、动作、对象或依据。比如“童子听到了什么？”每个选项逐字复制自原文。学习者先看到完整句子，再选择能回答问题的词句。重复片段在选项下写 `  第几处：2` 等从 1 开始的次数。编译时自动换算 UTF-16 字符位置。**排序** 用“排序”作标题类型，每项写成 `- [2] 打开匣子` 等，括号里填正确次序，文件中的排列是初始展示顺序。解析说明全部事件的依据和先后依赖。

## 给一节课写讲解

课文头部的“简介”用于课程介绍。正文是学习者可以自行打开的本课讲解。`## 正文` 之后直接用 Markdown 写教学内容，支持小标题、段落、列表、加粗、引用、对照表、代码块和 HTTPS 链接。可先给读者一个能直接观察的现象，再比较两种理解，最后用原文证据排除其中一种。正文到下一个内容章节（如“知识点”“原文”“单选”）结束。

每个“知识点”标题定义一个具体用法。“义项”“领域”“要诀”“讲解”分别用于教学和知识库。“例句”指向该义项的示范原文。每个新知识点自动产生一张知识卡，默认复用本课中该义项的所有题，至少有两段不同文字的原文。如需指定跨课语境，在知识点下写 `复习题：题目ID1 题目ID2`。普通课讲授的每个主要义项都应有练习。

后面一课再考已讲过的义项时，在课文头部按行填“回读”，每行依次填原知识点 ID 和本课新写的例句 ID。题目照常在“考点”里引用这个旧 ID。例如：

```md
回读：increase mountain
```

这里沿用[示例课](example-course/lesson.md)讲过的 `increase`；在新课中定义 `mountain` 原文并写一道确实要求判断升温的题。编译器按学习路径检查义项先后，核实练习里确有新语境，把新题接到已有知识卡。日常复习会在读者学完这门回读课后才抽取它的题，首次接触该义项时仍可从原课的不同语境中复习。单独校验这个单元时会一并读取它引用的课稿。

“原文”标题写“教学例句”或“古籍引文”。前者默认项目自撰，译文默认自撰；可用“原文权利”“译注权利”分别覆盖说明。用引用符号 `>` 写原文，在“译文”字段写自撰译意。同一原文只定义一次，多题可以引用同一 ID。古籍引文必须填写“出处”“作者”“版本”“原文权利”“译注权利”，可以加“底本链接”指向核对过的 HTTPS 链接。选段、译文和出处须逐一核对。

字段值可以直接使用中文标点、冒号与方括号；换行继续写同一字段时，用两个空格缩进，选项理由的续行用四个空格。正文使用 Markdown 的反斜杠转义。要在正文演示完整课稿标记，用代码围栏包住，里面的标题不会被识别成题目。

## 编排课程

| 文件 | 编辑内容 |
| --- | --- |
| course.md | 课程名、简介、等级、目标以及“单元”列表 |
| unit.md | 单元名、等级、“课序”列表和“检查”ID |
| 每节课的 .md | 可选讲解、知识点、例句与练习，练习按文件顺序出现 |
| check.md | 检查名称与练习；考点应来自本单元，至少涉及每课的一个义项 |

文件名仅用于整理，所有引用按 ID 匹配。“课序”按教学顺序列 ID，中间留一个空格。增加一课时复制邻近课文，给新实体分配 ID，并把课文 ID 加入单元的“课序”。所有已提供的课程和单元检查都能直接进入。编排时确保每个主要义项有练习，再用新的语境检查学习者能否迁移所学。

课程文件的“完整性”字段每行指定一个等级。续行缩进两个空格。各列依次为等级 ID、单元数、每单元课数、每课练习数、每次检查题数、该等级练习总数。例如：

```md
完整性：L1 4 3 8 6 120
  L2 4 3 8 6 120
```
独立的新课程可以自行设置或省略。可运行的微型范例是一门带两个练习、一项检查的气象课，完整源文件在 [example-course](example-course/)。

## 预览、校验与审核

1. 打开[作者预览](https://bzy-debug.github.io/wenyan-app/#/author)，选择已有课文或检查。粘贴或打开同 ID 的 .md，更新预览后可以直接跳转到每题、选择答案并检查反馈。编辑后下载课稿，将它保存回仓库的对应文件。新增课文需先在单元目录登记。
2. 开发时运行 `npm run dev`，保存 Markdown 后开发服务器会重新编译。`npm run validate:content` 在本地检查语法、ID、答案、选段、知识卡、多语境、学习目标覆盖与引用关系。单独编写某个单元时，`npm run validate:content -- --unit u05` 可在其他单元尚未齐备时检查本单元的三课和一次检查。提交前还需运行全书校验，以检查跨单元 ID、编排和总题数。报错如 `u01/01.md:48` 中的数字是行号。完整验证依次运行 `npm run check`、`npm run build` 和 `npm run test:e2e`。
3. 原文、知识点、题目、课文和检查默认“草稿”。人工复核后分别写“状态：已审核”和“审核人：…”；发布时用“已发布”。已发布实体所引用的原文、义项或题目也须完成发布。内容修改后按 [内容规范](CONTENT_GUIDE.md) 重新审核。

构建工具把 Markdown 编译为带类型的数据模块；学习端直接使用编译结果。浏览器作者预览、Node 内容校验和生产构建共用同一套编译逻辑。无需手工生成或同步另一份题库。

## 写一篇独立自读

`content/v1/readings` 中每个文件是一篇独立自读，可参考[亲历西陵峡](../content/v1/readings/03-gorge.md)。标题写 `# 自读：题名 {#稳定ID}`。头部注明文体、时代、出处、作者、版本、底本链接、原文权利、译注权利与状态，引用范围应与所据篇页对应。项目拟定的选段标题须在版本说明中标出。

“词注”按“词：简释”逐行写，续行缩进两个空格，每个所注词要在正文出现。先在 `## 正文` 下写完整的连续原文，以空行分段。每段自校另起 `## 自校：问题 {#稳定ID}`，用“证据”精确摘录正文，用“读法”解释从证据到理解的过程。读者可以先通读再打开词注和自校。选用陌生文本。校验会核查正课和检查中的原文与自读、试读文选是否有连续三十个字重合，也会核对单元检查是否整段复用本单元练习或示范。若有重合，另选确实能检验迁移的语境。

## 给原文加词注

读者可以答完后点「看解析」查词，也可以在本课讲解或知识库的「随文词义」里找回原句。每条只解释这个词在本句里的意思。相同的字在另一篇有不同读法时，写在另一篇的原文下。

```md
## 原文：教学例句 {#bridge-note}
> 驿卒闻水声，走告里人。
译文：驿卒听见水声，跑去告诉附近的居民。
词注：驿卒：在驿站当差的人。
  走：跑。
```

「词注」可以省略。第一条写在字段名后，其余每条另起一行并缩进两个空格。所注字词须逐字见于这段原文，同一段内只写一次。古籍引文照常填写出处、作者、版本及权利信息。
